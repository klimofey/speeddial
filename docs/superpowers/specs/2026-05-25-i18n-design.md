# Internationalization (i18n) — design

**Date:** 2026-05-25
**Status:** approved
**Builds on:** the SpeedDial MV3 extension (feat/speeddial-mvp).

## Goal

Localize all user-visible UI into **English, Russian, Spanish, German, French**,
with the language switchable in Settings (default = the browser's language). Adding
a new language should be one dictionary entry.

## 1. Core — `src/lib/i18n.ts`

- `Lang = 'en' | 'ru' | 'es' | 'de' | 'fr'` (the `Lang` type lives in `types.ts`).
- `messages: Record<Lang, Record<string, string>>` — flat key→string dictionaries.
  English holds the canonical current strings; the other four translate the same keys.
- `t(key: string): string` → `messages[current][key] ?? messages.en[key] ?? key`
  (fall back to English, then to the key itself, so a missing translation never
  shows blank).
- A module-level `current: Lang` (default `'en'`) with `setLang(l: Lang)`.
- `detectLang(): Lang` → from `navigator.language` (e.g. `ru-RU` → `ru`), else `'en'`.
- `LANGS: { code: Lang; label: string }[]` — for the Settings picker (labels are the
  language's own name, e.g. `Русский`, `Español`).

## 2. Settings field + default

- `Settings.language: Lang`; `DEFAULT_SETTINGS.language = detectLang()` (browser
  language for new users; stored value overrides via the existing merge).
- Settings panel gains a **Language** `<select>` from `LANGS`; changing it calls
  `updateSettings({ language })` and applies immediately.

## 3. Consumption — module-current + render-time set

- In `Board` (NewTab), at the **start of render**, call `setLang(settings.language)`.
  Because `settings` is reactive state, changing the language re-renders the tree and
  every `t(key)` call reads the new locale. No prop threading.
- Components import `t` from `../lib/i18n` and replace literal strings with `t('key')`.

## 4. String catalog (keys)

All user-visible text becomes keys with English = the current wording, e.g.:
- common: `save`, `cancel`, `close`, `edit`, `done`, `add_card`
- card editor: `edit_card`, `add_card_title`, `url`, `title`, `preview`,
  `mode_favicon`, `mode_letter`, `mode_upload`, `mode_url`, `mode_screenshot`,
  `find_better`, `allow_access`, plus scrape messages
  (`scrape_searching`, `scrape_found_more`, `scrape_no_extra`, `scrape_pick_or_allow`,
  `scrape_denied`, `scrape_selected`)
- settings: `settings_title`, `theme`, `theme_new`, `background`, `bg_theme`,
  `bg_color`, `bg_gradient`, `bg_image`, `search_engine`, `card_size`, `size_sm`,
  `size_md`, `size_lg`, `show_recent`, `suggestions`, `sugg_off`, `sugg_warn`,
  `screenshots`, `screenshots_warn`, `backup`, `export`, `import`, `language`
- clock: `clock`, `show_clock`, `clock_format`, `fmt_24`, `fmt_12`, `greeting_name`,
  `world_clocks`, `add_tz`, `greeting_morning`, `greeting_afternoon`, `greeting_evening`
- misc: `search_placeholder`, `recent`, `open_settings`, `clock_settings`
- The full dictionaries (all keys × 5 languages) are defined in the implementation
  plan's first task.

`greeting(hour)` is changed to return a key (`'greeting_morning' | 'greeting_afternoon'
| 'greeting_evening'`); `Clock` renders `t(greeting(hour))`. Per-card `Edit`/`Delete`
aria-labels that embed the site title stay templated but use translated verbs
(`t('edit')`/`t('delete')`).

## 5. Why existing tests mostly survive

In the test env `navigator.language` is `en-US` → default `en`, and the English
dictionary equals today's wording, so `t('save')` renders `"Save"` exactly as before.
Tests asserting English strings keep passing. The exceptions to update: `greeting`
(now returns keys) and any test that asserted the exact greeting phrase; plus new i18n
tests.

## 6. Testing

- `i18n.ts`: `t` returns the active language's string, falls back to English for a
  missing key, then to the key; `detectLang` maps `ru-RU`→`ru`, unknown→`en`;
  `setLang` switches what `t` returns.
- A component test: render with `language: 'ru'` (and `setLang('ru')`) shows a
  Russian string (e.g. the Add-card button); default render stays English.
- `greeting` tests updated to assert the keys; `Clock` renders the localized greeting.
- Existing English-string tests remain green.

## 7. Out of scope

- Localizing `formatTime`/number formats (digits are universal; the clock stays
  `en-US`-formatted for determinism).
- RTL languages / pluralization rules (current strings need neither).
- Translating user content (card titles, world-clock labels) — only the app's own UI.
